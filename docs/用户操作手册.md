# 板检数据核验工具 — 用户操作手册

> 面向产线工人、QC 同事、板检开发同事。
> 阅读时间: 5 分钟。

---

## 一、这是什么?

一个本地工具,在每批次板检完成后,**自动对比** "板检日志" 与 "追溯平台"的数据,
发现错误后立即报告,把 Bug 拦截在出厂前。

```
原本:  板检 → 上报 → 出厂 → 用户投诉 → 才知道错了
现在:  板检 → 上报 → 【本工具核验】→ 出厂前就知道错了
```

---

## 二、典型用户

| 角色 | 使用场景 |
|---|---|
| 产线工人 | 每批次完成后,点 4 个按钮生成报告 |
| QC 同事 | 每天查看报告汇总,把问题反馈给开发 |
| 板检开发 | 看"AI 分析报告"的根因,修复 Bug |

## 三、操作步骤(5 分钟学会)

### 步骤 1: 启动工具

双击 `板检数据核验工具.exe`,会自动打开浏览器:
```
http://127.0.0.1:5050
```

如果浏览器没自动打开,手动复制这个地址。

### 步骤 2: 选择设备型号

在页面顶部下拉框里,选你今天生产的产品型号,例如:
- `A02FG` (4G 网关)
- `B05WX` (待添加)
- ... 

### 步骤 3: 上传板检数据

点击 **"📂 上传"** 按钮旁的 **"选择文件"** 按钮,选你的板检日志或数据库文件:

| 支持格式 | 说明 |
|---|---|
| `.txt` `.log` `.md` | 文本日志(板检主机生成的串口日志) |
| `.db` `.sqlite` `.sqlite3` | SQLite 数据库文件 |
| `.csv` | CSV 表格(已导出的板检记录) |

**注意:** 每个产品支持的格式可能不同,以该设备的规则为准。

### 步骤 4: 上传平台 CSV

从追溯平台导出本批次的 CSV,然后点击另一个 **"上传"** 按钮。

### 步骤 5: 开始核验

点击 **"⚙️ 开始核验"** 按钮。

等待几秒到几十秒(取决于数据量),页面会自动显示结果:

```
┌─────────────────────────────────────────────┐
│  总设备数: 150                              │
│  ✅ 完全一致: 1                             │
│  ❌ 字段不一致: 63                          │
│  ⚠️ 仅原始有: 0                            │
│  ⚠️ 仅平台有: 86                           │
└─────────────────────────────────────────────┘
```

### 步骤 6: 下载报告

页面下方有三个下载链接:

| 报告 | 格式 | 用途 |
|---|---|---|
| 📊 **详细对比表** | .xlsx | 给开发看,每台设备的字段对照 |
| 📤 **重传数据** | .csv | 给平台管理员,直接上传修复数据 |
| 🤖 **AI 分析报告** | .md | 给开发看,描述错位现象与根因 |

把这三个文件转发给对应的同事。

### 步骤 7: 关闭工具

回到 EXE 的命令行窗口(黑色的那个),按 `Ctrl+C` 退出。

## 四、常见问题

### Q1: 双击 EXE 后没反应?

A: 等待 3~5 秒(EXE 启动需要时间)。如果还不行:
1. 检查是否有杀毒软件拦截
2. 试试"以管理员身份运行"
3. 查看是否报错"缺少 xxx.dll"——通常是缺少 Visual C++ 运行库

### Q2: 提示"LLM API Key 未设置"?

A: 这是**正常的**!本工具主要靠规则核验,不需要 LLM。只有当某条数据正则解析不出来时,才会用到 LLM。

如果想启用 LLM 兜底:在页面最上方的 **"⚙️ LLM 设置(可选)"** 区块里,填写 API Key 并点击"保存设置"、"测试连接"即可。也可以请开发同事帮你配置。

### Q3: 报告显示"无明显异常",但我知道数据有问题?

A: 请:
1. 确认上传的文件**确实是本批次**的(不要混批次)
2. 确认选择了**正确的设备型号**
3. 把问题样本(.txt 日志片段)转发给开发,让他检查规则是否覆盖你的场景

### Q4: 上传文件后报"500 错误"?

A: 通常是:
- 文件太大(超过 200MB)→ 拆分文件
- 文件格式损坏 → 用记事本打开看是否可读
- 不支持的编码 → 转为 UTF-8

### Q5: 重传 CSV 上传平台后没生效?

A: 重传 CSV 的列结构与平台导入模板一致。如果平台不接受:
- 检查列名是否一致(可能因平台版本不同)
- 检查是否平台有"导入限制"(比如单次最多 1000 条)

### Q6: AI 分析报告里没看到我关心的内容?

A: 报告内容由 LLM 自动生成,可能漏掉某些细节。建议:
- 详细对比表(.xlsx)能看到每台设备的字段对照
- 如果 LLM 未启用,只有固定模板的内容

## 五、报告解读

### 状态着色

| 状态 | 颜色 | 含义 | 怎么修复 |
|---|---|---|---|
| ✅ MATCH | 绿色 | 4 个字段(SN/MAC/ICCID/追溯码)完全一致 | 无需操作 |
| ❌ MISMATCH | 红色 | 部分字段在两端不同 | 用 xlsx 的"原始 SN/MAC"列覆盖平台数据 |
| ⚠️ RAW_ONLY | 黄色 | 板检做了,但平台没收到 | 检查上报链路,或用重传 CSV 补录 |
| ⚠️ PLATFORM_ONLY | 黄色 | 平台有记录,但板检日志找不到 | 检查日志是否归档丢失 |

### A02FG 已知 Bug

如果报告显示**几乎所有设备的 SN 都不一致**,但 MAC/ICCID/追溯码一致,
这通常是 **A02FG 板检软件 Bug**:把内部生成的 UUID 顶替了真实 SN 上报。

修复方法:
1. 把重传 CSV 里的"原始 SN"列覆盖平台上的"SN"列
2. 通知开发修复板检上位机的 SN 写入逻辑

## 六、文件位置

工具运行期间产生的文件:

| 文件类型 | 位置 |
|---|---|
| 上传的原始文件 | `C:\Users\<你>\>\.agent\uploads\` |
| 生成的报告 | `C:\Users\<你>\>\.agent\outputs\` |

要清理旧报告,直接删除 `~/.agent/outputs/` 下的文件夹即可。
