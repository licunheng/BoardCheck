# 04 - 交付物出现「COM77:收 :MAC:」字段名(2026-08-14)

> 状态:🟢 已修复(`extractor._extract_field_value` 捕获组约定)

## 现象

用 agent 自带的"新增设备配置"生成 F16G 后,交付物里出现的不是字段值,而是
`COM77:收 :MAC:` 这种**串口 + 字段名**的标签——用户要的是具体值,不是"哪个 COM 口哪个字段"。

## 根因

LLM 生成的配置里,`context_anchor` 只是个**定位前缀**(后面没有括号),如
`COM\d+:收\s*:mac:`;而真正"值"的捕获组放在 `regex` 里,如
`COM\d+:收\s*:mac:\s*([0-9A-Fa-f]{12,14})`。

旧的 `_capture()` 逻辑:只要锚点命中且 `lastindex` 非空就取 `group(1)`,否则取 `group(0)`。
当锚点**没有捕获组**时,`lastindex` 为 None,于是返回 `group(0)`——**整个匹配到的前缀**,
即 `COM77:收 :MAC:`,把标签当成了值。

## 修复

重写 `_extract_field_value`,取值优先级明确:

1. `context_anchor` **带捕获组** → 取 `group(1)`(最权威,A02FG 约定);
2. 锚点只是前缀(无捕获组)→ **回退到 `regex`** 的捕获组 `group(1)`;
3. `regex` 无捕获组 → `group(0)`(裸值模式)。

关键约束:`context_anchor` 若没有捕获组,它只是定位前缀,**绝不能把整个前缀当字段值返回**。
同时在生成 prompt 里写明捕获组约定:"每个字段的 regex 或 context_anchor 里必须有一个用括号包住『字段值本身』的捕获组"。

## 验证

回归测试覆盖两种约定:A(锚点带组)与 B(锚点前缀 + regex 带组),两者都取到值而非标签;
此前 `COM77:收 :MAC:` 字样不再出现在交付物。

## 教训

- **捕获组约定是抽取的生命线**:标签和值必须靠括号分开;锚点可以只负责"定位",值一定来自捕获组。
- 对 LLM 产物要做**确定性防御**:即便它没按约定写捕获组,抽取器也要能兜底取到值。
