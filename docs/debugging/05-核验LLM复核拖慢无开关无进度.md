# 05 - 核验被 LLM 复核拖慢 15 分钟、无开关、无进度(2026-08-16)

> 状态:🟢 已修复(LLM 复核开关 + 核验后台化 + 进度)

## 现象

开启 LLM 复核后,「开始核验」按钮一直转圈 15 分钟+,期间无任何进度反馈;且 LLM 复核写死在每台设备的 `extraction_rules.json`(`llm_verification.enabled`),普通工人在界面上**没法关**。日志显示独立抽取按 200 行切 21 块、每块 40~60 秒且全 0 条,白跑。

## 根因

1. LLM 复核**默认开且不可关**(开关埋进设备配置,非界面可控);
2. `/api/verify` 是**同步阻塞**接口,慢任务会卡死前端;
3. 当时还没有"空转探针",LLM 抽 0 条也静默继续。

## 修复

1. **LLM 复核开关(人工可控)**:主开关(默认**关**)+ 两个子开关——
   - 独立抽取交叉验证(很慢,默认关);
   - 不一致记录复核(较快,默认开);
   持久化到 `~/.agent/config.json`,优先级「界面开关 > 设备配置」。
2. **核验后台化 + 进度**:复用设备生成的 job 机制,`/api/verify` 改为提交后台任务、前端轮询 `/api/verify/status`,能看到「正在 LLM 复核 chunk 3/21」这类进度。
3. `llm_review.llm_reconcile_extraction / llm_review_comparison` 增加显式 `enabled` 参数。

## 验证

开关关时核验秒级完成、纯确定性;开时前端有进度、后台不卡。

## 教训

- **慢且非必需的能力必须给用户开关,且默认关**——确定性主流程不该被 LLM 拖慢。
- **后台任务 + 进度轮询是慢任务的标配 UI**,别让工人盯着转圈猜。
