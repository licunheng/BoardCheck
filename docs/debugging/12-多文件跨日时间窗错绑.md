# 12 - 多文件日志跨日时间窗错绑(2026-08-22)

> 状态:🟢 已修复(`agent/core/verifier.py` 文本日志按文件分别抽取 + source_line 全局偏移)
> 触发用户反馈:用户传入 3 个 txt(3 天板检记录)+ 1 个 csv,EXE 报告里"大部分空白 / 大量 MISMATCH",初步以为是抽取问题,实际是多文件合并的架构 bug。

## 现象

用户上传 N 个 txt + 1 个 csv(平台),xlsx / md 报告里:
- 「字段不一致」数量暴增(可达原始数据的 50%+)
- 「原始 SN/MAC/ICCID 列」看起来缺失或乱跳
- 数据质量报告里 `1:1 冲突` 大量出现
- 一台设备的 SN 错绑给另一台设备

## 根因

`_preprocess_raw_files` 把多个文件的 `kept_lines` 简单拼接成一个列表:

```python
# 旧逻辑(verifier.py:_preprocess_raw_files)
merged_lines = []
for p in paths:
    pp = preprocess_raw_file(p, rules)
    merged_lines.extend(pp.kept_lines)   # ← 简单拼接
return PreprocessResult(kept_lines=merged_lines, ...)
```

然后 `extract_from_text_log(merged_lines, rules)` 在这个全局列表上做时间窗绑定:
- 时间戳只有 `HH:MM:SS`,没有日期
- file1 末行 `23:59:50` 与 file2 首行 `00:00:10` 在拼接列表里**仅相隔 10 秒**
- 实际相隔 8 小时+

SN/ICCID/MAC 绑定走 `_nearest_after_same_port(parsed, anchor, kind, window_seconds)`,120s 窗口:
- file2 设备的 trace_code anchor 在 `00:00:30`
- 跨文件后,`23:59:50`(file1)的 SN 与 `00:00:30`(file2)被视为 40 秒内 → SN 错绑
- 一台设备的 SN 被绑给另一台 → 1:1 冲突 → dedupe 标记 `confidence=low`
- 报告里大量冲突 + 数据"看起来缺失"

更糟的情况:同一 MAC 跨日出现,跨日 SN 全部绑错,dedupe 把它们 drop 或合并到错误的 trace_code 下 → 报告「空白」。

## 修复

`agent/core/verifier.py` 新增 `_extract_text_logs_per_file`,核心思路:

1. **每个文件独立预处理 + 抽取**:每个文件单独走 `preprocess_text_log` + `extract_from_text_log`,SN/ICCID/MAC 绑定只在单文件内的时间窗内有效。
2. **records 合并 + source_line 全局化**:每条 `DeviceRecord.source_line` 加上累计偏移,映射到全局 merged_kept_lines,LLM 复核(`_grab_context` / `_conflict_context`)用 source_line 索引时仍正确。
3. **merged_kept_lines 保留**:LLM 上下文查找仍然走全局索引,只是「时间窗过滤」由 LLM 自己按 timestamp 判定,跨日行自然不会被错误关联(LLM 看到 `23:59` 紧接 `00:00`,应能识别为日界)。
4. **总统计同步更新**:`preprocessed.total_input_lines` / `total_kept_lines` 改为跨文件累计。

## 验证

新增回归测试 `tests/test_device_generation_fixes.py::test_extract_text_logs_per_file_no_cross_day_binding`:
- 构造 file1(23:59:50 发 SN=...000100001) + file2(00:00:10 起完整循环,SN=...000100002)
- 修复前断言会失败(file2 设备绑到 file1 的 SN)
- 修复后断言通过(file2 设备绑对 file2 的 SN,跨日不错绑)

## 教训

- **时间戳不带日期时,绝不能跨文件合并时间窗**——`_extract_*` 必须按文件边界隔离。这是工程通则,任何依赖时间窗的逻辑都要先确认时间单位(秒/分钟/小时)是否携带足够粒度。
- **跨文件边界 = 跨日期边界 = 跨"逻辑墙"**:文件是天然的分隔符,不要试图用更聪明的算法跨过它。
- **source_line 全局偏移是干净的对接方式**:LLM 上下文查找依赖 `source_line` 索引 merged kept_lines,我们只要保证"全局索引一致"即可,不需要改造 LLM 复核函数。
- **per-file 抽取不影响 dedupe 与冲突检测**:dedupe 仍能在跨文件合并的 records 上做 1:1 校验,反而能发现"同 trace_code 跨日重测"这种异常。

## 规则沉淀

- **RULE-MULTI-FILE-EXTRACT**:文本日志按文件分别预处理+抽取,SN/ICCID/MAC 绑定限定在单文件内;LLM 上下文仍走 merged kept_lines(source_line 全局化)。
- **RULE-TIME-WINDOW-NO-DATE**:任何只携带 `HH:MM:SS` 时间戳的日志,跨文件处理时必须按文件独立,不可合并时间窗。
