# 06 - 平台列名映射幻觉:SN/MAC/ICCID 在 CSV 中不存在(2026-08-16)

> 状态:🟢 已修复(内容嗅探 .xls 导入 + 列名模糊匹配自动纠错)

## 现象

选 txt + csv 核验 F16G 时报错:

```
平台 CSV 列名映射有误...sn → 列名 'SN' 在 CSV 中不存在
(CSV 实际列为: 主键, 产品名称, 追溯码, 设备编号, 授码权2, 蓝牙mac, plc模组mac,
4G信息, 写入SN, 客户三元secret, 三元mac, 产品ID, 模组mac, 网关mac, 创建时间, ...)
mac → 列名 'MAC' 不存在 ...
iccid → 列名 'ICCID' 不存在 ...
```

## 根因

生成配置时,LLM **看不到真实 CSV**,凭空把列名写成通用名 `SN/MAC/ICCID`,而真实表头是中文(写入SN/蓝牙mac/4G信息)。这是兜底校验(`_validate_platform_columns`)正常拦截的结果——**没让用户拿到假的全对**。

### 关键澄清(本轮才查明)

- **平台原生导出是 `.xls`,不是 CSV**;之前的 CSV 是"用工具转了一道",导致表头漂移(A02FG 用「A系列uuid」、F16G 用「设备编号」)。
- **SN = 设备编号**(实测 F16G 的「写入SN」列为空,真实 SN 在「设备编号」列)。

## 修复

1. **平台 .xls 原生导入**(`file_reader.read_spreadsheet`):按文件内容嗅探魔数——
   `PK`→xlsx(openpyxl)、`OLE2`→真 .xls(xlrd)、`<`→HTML 表、否则 CSV;杜绝"中间转换"造成表头漂移。
2. **列名模糊匹配自动纠错**(`verifier._resolve_platform_columns`):
   - 先精确匹配(忽略大小写/空白/下划线);
   - 对不上就按「字段语义同义词 + 文本相似度」打分,取置信度最高的真实列名自动采用;
   - 纠错成功自动写回 `device.json`,配置自愈;实在匹配不上才报错并给"最接近的是哪一列"。
3. **同义词表把「设备编号」提到 sn 最前**(优先级高于 写入sn/serial/uuid)。

## 验证

故意把 F16G 映射还原成幻觉名 `SN/MAC/ICCID`,跑核验,自动纠错为 `设备编号/蓝牙mac/4G信息`,置信度 100%,比对正常。

## 教训

- **平台 .xls 是标准与真值**,以平台为准再回日志定位;别让"中间转换"污染表头。
- **LLM 看不到的东西它就会编**;凡是要 LLM 生成的映射,要么喂真实样例,要么运行时兜底校验。
