# 13 - 追溯码前缀跨批次多变,A02SG 只认 F068XYXI8F 整批漏抽(2026-08-22)

> 状态:🟢 已修复(A02SG 追溯码前缀放宽为 `F068[0-9A-Z]{6}[0-9A-Z]{12}`)
> 触发用户反馈:`F068XYXI6H0001F33A4113` 在 6/17 板检日志里有,但对比表说"板检日志里没有"。

## 现象

用户上传 6/17、6/18 三天日志 + 平台 CSV,对比表里大量平台记录被标为
「仅平台有,板检日志未找到」(`PLATFORM_ONLY`)。用户点名 `F068XYXI6H0001F33A4113`:
日志里明明有,报告却说没有。

## 根因

A02SG 配置的 `trace_code` 正则把前缀锁死在 `F068XYXI8F`:

```json
"regex": "(?:回复)?追溯码[:：]\\s*(F068XYXI8F[0-9A-Z]{12})"
```

但 A02SG 追溯码前缀**随生产批次变化**。平台 CSV 里 A02SG 产品实际出现的前缀:

| 前缀 | 板件时间批次 | 平台条数 |
|---|---|---|
| F068XYXI6H | 2026-06-17 | 171 |
| F068XYXI6I | 2026-06-18 | 21 |
| F068XYXI8C | 2026-08-12 | 100 |
| F068XYXI8F | 2026-08-15 | 100 |
| F068XYXI7U | 2026-07-30 | 10 |
| F068ZHHI7K / F068ZHHI8D | 零星 | 2 |

6/17 日志用 `F068XYXI6H`(173 条回复追溯码),旧正则一条都匹配不上 →
整批抽取 0 条 → 平台 171 条全部 `PLATFORM_ONLY`。

```
6/17 日志 输入 22137 行 → 保留 923 行 → 抽取 0 条(旧正则)
修复后              → 保留 923 行 → 抽取 172 条(172 唯一追溯码)
```

## 追溯码格式

```
F068XYXI6H0001F33A4113
F068 (4 家族码) + XYXI6H (6 变体) + 0001F33A4113 (12 尾段) = 22 位
```

前缀结构:`F068` + 6 位字母数字(随批次变)+ 12 位尾段(后 12 位 = MAC)。
各设备家族前缀:

- A02SG: `F068` + 变体
- A02EG: `F069` + 变体
- A02FG: `F070` + 变体(见 6/18 混合日志)
- F16G: `F176` + 变体

## 修复

`devices/A02SG/extraction_rules.json` + `agent/devices/A02SG/` + `output_config/A02SG/`:

```json
"regex": "(?:回复)?追溯码[:：]\\s*(F068[0-9A-Z]{6}[0-9A-Z]{12})"
```

- `context_anchor` / `field_anchors.trace_code` 同步
- `device.json` 的 `field_definitions.trace_code.pattern_in_raw` 同步
- 前缀保留 `F068`(A02SG 家族),只放宽 6 位变体段

**为什么不直接放开成 `F[0-9A-Z]{21}`?**
因为 6/18 是 A02SG+A02FG 混合日志,A02FG 用 `F070` 前缀。
若放得太宽,A02SG 配置会把 A02FG 的追溯码也抽进来 → 混产品错绑。
`F068` 前缀能精确隔离 A02SG,同时覆盖它的全部批次变体。

## 验证

| 场景 | 修复前 | 修复后 |
|---|---|---|
| 6/17 日志抽取 | 0 条 | 172 条(172 唯一追溯码) |
| `F068XYXI6H0001F33A4113` | 未命中 | ✅ 命中(sn=FA000001400001240260617000100054) |
| 6/17 平台比对 | 0 命中 | 171/171 命中 |
| 6/18 混合日志 | 0 条 | 22 条(仅 F068XYXI6I,A02FG 的 F070 正确排除) |
| 6/18 平台比对 | 0 命中 | 21/21 命中 |

## 教训

- **追溯码前缀不是稳定的 10 位字面量,是"家族码 + 批次变体"**:A02SG 的 `F068` 是家族码,
  后面 6 位(XYXI6H/XYXI8F/ZHHI7K 等)随固件/批次变化。配置时绝不能只写死某批次看到的一个完整前缀。
- **写正则前先扫平台 CSV 全部唯一前缀**:统计前缀分布(本例 7 个变体),再决定"哪些部分是家族常量、哪些是变体段"。
  家族常量保留(隔离同族不同产品),变体段用 `[0-9A-Z]{n}` 放宽。
- **「日志里有但报告说没有」优先怀疑正则太窄**:双形态(#11)+ 多前缀(#13)是同一症状的两类根因,排查顺序:先 grep 日志确认值存在 → 检查过滤 keep_patterns → 检查抽取 regex。
- **配置放宽必须兼顾混打日志隔离**:放得太宽会把同族其他产品(A02FG/F070)误抽进来。家族码是天然隔离边界。

## 规则沉淀

- **RULE-TRACE-PREFIX-SCAN**:新设备/老设备配置改动前,先扫平台 CSV 全部唯一追溯码前缀分布,家族常量保留、批次变体段用 `{n}` 放宽。
- **RULE-TRACE-PREFIX-ISOLATION**:放宽前缀时保留家族码隔离同族产品(A02SG=F068, A02EG=F069, A02FG=F070, F16G=F176),禁止全放开。
