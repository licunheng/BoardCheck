# 02 - 通用抽取器被 A02FG 硬编码正则绑死(2026-08-13)

> 状态:🟢 已修复(`extractor._parse_key_lines` 通用化)

## 现象

新设备的抽取逻辑没有按 `devices/<code>/` 下的 `field_extractors` 生效——
即便为新设备写了规则,抽取结果仍按 A02FG 的格式走,导致抽取不到或抽错。

## 根因

`extract_from_text_log` 内部的 `_parse_key_lines` **硬编码了 A02FG 的正则**,
没有读取设备规则里的 `rules.field_extractors`。等于"规则插件化"做了一半:
配置文件能加,但抽取引擎根本不看它。

## 修复

把 `_parse_key_lines` 改为**完全通用**:
- 遍历 `rules.field_extractors`(来自设备 JSON),用 `_extract_field_value` 抽取每行;
- 不再引用任何 A02FG 专属字面量;
- 同时把 `_apply_post_process` 统一做 trim/upper 等后处理。

这样 `devices/<code>/` 下的四件套才真正成为"无需改代码即可扩展"的规则插件。

## 验证

新设备(F16G)按其自身 `field_extractors` 正确抽取;回归测试保留 A02FG 与新设备两种约定的覆盖。

## 教训

- **"插件化"要彻查到底**:配置入口开放还不够,消费配置的引擎必须通用,否则是"伪插件化"。
- 硬编码某台设备的逻辑,要一律下放到 `devices/<code>/` 配置。
