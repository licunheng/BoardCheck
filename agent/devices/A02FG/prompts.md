## 设备类型识别

本设备为 **A02FG 4G 网关**,因此必须校验 ICCID 字段。

## 字段抽取规则

### SN (设备序列号)
- 格式:`FA0000014000012402608[0-9A-F]{14}`,共 32 位十六进制
- 仅出现在 **板检主机下发的命令**中,日志行模式:
  ```
  COM\d+:发:568121440200(FA0000014000012402608[0-9A-F]+)
  ```
- **不要**从设备回复中抽取 SN(回复中不带 SN)

### MAC (蓝牙 MAC 地址)
- 格式:12 位十六进制(以 `0001` 开头)
- 日志行模式:
  ```
  COM\d+:收mac:([0-9A-F]{12})
  ```

### ICCID (4G SIM 卡号)
- 格式:19~20 位,以 `8986` 开头
- 日志行模式(注意原文写作 "CCID" 不是 "ICCID"):
  ```
  COM\d+:4G\s+CCID:([0-9A-F]{19,20})
  ```

### 追溯码
- 格式:23 位,以 `F070XYXI8` 开头,后 14 位十六进制
- 日志行模式:
  ```
  COM\d+:回复追溯码:(F070XYXI8[0-9A-F]+)
  ```
- **追溯码后 8 位必须等于 MAC 后 8 位**(设备固化的派生关系)

## 同一台设备的"测试循环"

板检日志中,一台设备的完整测试由 4 行构成(时间窗 5 分钟内):
1. `COM\d+:发:...FA000001...` (主机下发命令,带真实 SN)
2. `COM\d+:收mac:0001XXXX...` (设备回读 MAC)
3. `COM\d+:4G CCID:8986...` (设备回读 ICCID)
4. `COM\d+:回复追溯码:F070XYXI8...` (设备回读追溯码)

**绑定原则**:
- 以追溯码回复时间点为锚点
- 在其前后 5 分钟窗口内,匹配同一组 SN/MAC/ICCID
- 多端口(COM94、COM3)并行测试时,各自独立计数

## 已知陷阱(防呆)

1. **平台记录的 SN 是错的**:平台记录的 "A系列uuid" 列(32位 hex)并非真实 SN,真实 SN 仅存在于日志下发命令中
2. **日志中 "CCID" 是拼写错误**:实际就是 ICCID
3. **多串口并行**:COM94 和 COM3 同时测试,SN 计数器独立
4. **同一 SN 多次下发**:重试时同一命令可能下发 2~4 次,需去重
5. **跨天测试**:SN 日期字段可能与实际回复追溯码的日期不同
