## Why

当前引擎与配置生成器在「上百种设备、日志格式五花八门」的场景下，暴露出三类互相纠缠的问题：

1. **确定性引擎里残留通用假设**：MAC 派生判据写死「末 8 位」、绑定只看「同串口+时间最近」、trace_code 多形态行全成锚点——这些假设只对个别设备成立，换设备就错绑。
2. **配置生成不够充分**：生成四件套是"一次成稿 + 宽松自检"，没有把每台设备的权威锚点、派生关系（实测长度）、头尾码剥离、平台列名、值合法性**逐一深挖并实测**，导致配置从源头就埋雷。
3. **LLM 运行时静默失效**：复核/兜底调用空转（每 chunk 0 条）却不告警，让人误以为"交叉验证做过"。

根本症结是：**该交给 AI 充分思考的（配置），现在想得太浅；该由引擎兜底的（确定性质量），才刚开始有；该让用户看见的（LLM 是否生效），现在不可见。**

本方案把"该改的引擎底座"和"该精进的生成管线"统一成一套，目标：**配置生成一次到位且经实测验证，引擎只做通用、可配置、可兜底的事，LLM 是否生效全程可观测。**

## What Changes

### Part 1：确定性引擎底座（代码，必改，向后兼容）

- **E1 派生关系可配置化**：引擎不再硬编码「末 8 位」。新增从设备配置读取派生规则（如 `mac_derived_from_trace: true` + `mac_trace_suffix_len: 12`），校正/绑定/LLM 裁决统一按配置的派生长度与关系执行。老设备未配置该规则时行为不变。
- **E2 绑定策略升级**：绑 MAC/SN/ICCID 时**先用配置里的派生关系筛**(命中即用)，找不到再回退「同串口+时间窗」；时间窗可配置（默认收窄）。
- **E3 trace_code 锚点唯一化**：多形态日志行时，抽取器只取配置里标记的「权威形态」(如"发:")，同(码,串口) 不再重复成锚点；无权威形态时取首个，保证一设备一锚点。
- **E4 LLM 复核空转探针**：复核层统计 chunk 成功/0条/解析失败数，全空转则在结果与报告中显式告警"复核未生效"，不显示"分歧 0"造成假象。

### Part 2：配置生成管线精进（LLM 调用，多调用不限次数，准确性第一）

- **G1 逐字段穷举 + 权威形态判定**：把形态穷举拆成「按字段单独调用」，每字段强制输出"所有形态（含样例行号）+ 权威锚点（唯一稳定）"。
- **G2 派生关系实测**：生成期新增节点，让 LLM 从样例里**实测**派生关系——数出"平台 MAC 是追溯码第几位到第几位"、推导 SN 头尾码剥离规则，输出可执行的量化结论（suffix_len / strip 规则），而非自然语言。
- **G3 生成后自检加「值合法性」门槛**：抽出的字段值若含 `COM`、含冒号、长度明显异常（像标签不像值）→ 直接判失败回炉。
- **G4 审查者节点**：生成完四件套后再调一次 LLM 扮演审查者，挑逻辑漏洞（锚点会重复吗？派生成立吗？头尾码剥对了吗？），审查意见作为回炉输入。
- **G5 回炉不设死次数 + 带完整证据**：回炉时把自检报告+原始样例+当前配置一起喂回；上限放宽（如 5 轮），仍不达标明确标「需人工补充规则」。
- **G6 大任务拆小**：四件套拆分生成/校验，降低单次输出被推理模型 thinking 榨干的概率。
- **G7 样例不足保守策略**：标注哪些正则是推测的，配合"生成后须真实日志验证再上生产"。

### Part 3：报告与界面

- **R1** 报告 + 前端展示"LLM 复核是否生效"（生效/空转告警）。
- **R2** 界面保留 LLM 复核开关（主开关默认关，独立抽取默认关、比对复核默认开），并展示生成配置时的自检质量报告。

## Capabilities

### New Capabilities

(无)

### Modified Capabilities

- `device-rule-plugin`: `device.json`/`extraction_rules.json` 需支持「派生关系（长度可配）」「权威锚点形态」「值合法性约束」「头尾码剥离规则」等新键；老键兼容。
- `board-test-verification`: 抽取/绑定/比对按"派生优先+时间窗兜底""锚点唯一化"执行；结果带 LLM 复核生效标记。
- `llm-prompt-engine`: 复核调用加空转探针；生成期 prompt 升级为"逐字段穷举+实测推导+审查回炉"多节点。
- `rule-self-check`: 自检门槛升级为"抽全率 + 重复率 + 1:1 冲突 + 值合法性 + 平台列名命中"五维硬门槛。
- `factory-gui`: 展示复核生效状态与配置生成质量报告。

## Impact

- **代码**: `agent/core/extractor.py`(派生可配/绑定/锚点唯一)、`agent/core/llm_review.py`(空转探针)、`agent/core/device_generator.py`(五阶段→多节点深挖管线)、`agent/core/reporter.py`(复核生效标记)、`agent/core/quality.py`(复用派生判据)。
- **配置**: `devices/<code>/` 四件套 schema 扩展(向后兼容)。
- **API/界面**: 核验结果与生成结果结构新增字段；前端展示复核生效与质量报告。
- **依赖**: 无新增。
- **测试**: 补 MAC 错绑、锚点唯一化、值合法性、空转探针、派生可配五类回归。

## 决策点（供审核拍板）

| # | 决策点 | 建议 | 备选 |
|---|--------|------|------|
| 1 | 派生关系 | 引擎可配置(长度+是否派生),由生成期实测写入 | 保留硬编码末8位(不推荐) |
| 2 | trace_code 锚点 | 配置权威形态(如"发:"),无则取首个 | 多形态全留(不推荐) |
| 3 | 绑定窗口 | 派生优先 + 窗口兜底(默认收窄至60s,可配) | 保留300s |
| 4 | 生成回炉次数 | 上限放宽(5轮)+ 达标才交付 | 固定3轮 |
| 5 | 审查者节点 | 加(一次额外调用换准确率) | 不加 |
| 6 | LLM 空转 | 探针+显式告警 | 告警+建议换模型 |

## 验收标准

- 同一份 F16G 日志重跑: MAC ✗ 由 34 → ≈0;quality.conflicts 由 25 → 0;trace_code 锚点数 ≈ 真实设备数。
- 生成配置时: 派生长度/头尾码/权威锚点被实测写入配置;自检含值合法性;回炉直到达标。
- LLM 复核空转时,报告与界面明确提示"复核未生效",不再显示"分歧 0"。
- A02FG 等老设备不回归。
