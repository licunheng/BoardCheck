# Design — 统一演进方案:引擎底座 + 配置生成管线精进 + LLM 可观测

## 设计总原则

```
┌────────────────────────────────────────────────────────────┐
│  引擎(代码,通用,不改)   =  提供「可配置能力 + 确定性兜底」     │
│  配置(四件套,每设备)     =  AI 深挖 + 实测后写进去的「事实」    │
│  LLM                    =  兜底与第二视角,且「是否生效」可观测  │
└────────────────────────────────────────────────────────────┘
```

核心思想一句话:**AI 想透的写进配置,引擎照配置执行,LLM 兜底且不静默失效。**

## 一、引擎底座(Part 1)

### E1 派生关系可配置化

设备配置 `field_constraints` 新增(向后兼容):

```jsonc
{
  "mac_derived_from_trace": true,   // 是否派生
  "mac_trace_suffix_len": 12,        // 派生:MAC = 追溯码后 N 位(默认12)
  "sn_strip_prefix": "",             // SN 头码剥离(可空)
  "sn_strip_suffix": "46"            // SN 尾码剥离(可空)
}
```

- `extractor._mac_matches_trace` / `_find_mac_by_trace_suffix` / `llm_review` 的派生判据,
  全部从配置读 `mac_trace_suffix_len`(缺省 12),不再写死 8。
- 老设备未配置派生规则 → 跳过派生校正,行为不变。

### E2 绑定策略:派生优先 + 时间窗兜底

```
绑 MAC 时:
  ├─ 若 mac_derived_from_trace=true:
  │     在同串口 mac 行中,优先选「前 mac_trace_suffix_len 位 == 追溯码末 N 位」者 → 命中即用
  │     若无 → 进入时间窗兜底
  └─ 时间窗兜底: 同串口 + 时间最近, window_seconds 可配(默认收窄)
```

### E3 trace_code 锚点唯一化

- `field_extractors.trace_code` 增加 `authoritative_forms`(如 `["发\\s*:"]`)。
- 抽取时对同(追溯码, 串口) 只保留权威形态命中者;无权威形态命中时取首个,保证一设备一锚点。

### E4 LLM 复核空转探针

`extract_records_with_llm` 统计 `total_chunks / success_chunks / zero_chunks / parse_fail_chunks`;
`success_chunks == 0` → `llm_meta.extraction_effective = false`,报告与界面显式告警。
比对复核 `reviewed == 0 且存在不一致记录` 同样告警。

## 二、配置生成管线(Part 2,多节点深挖,多调用不限次数)

```
输入: 描述 + 样例日志 + 样例CSV
   │
   ▼
G1 逐字段穷举 + 权威形态判定        ← 每字段单独一次调用
   │      输出: 每字段所有形态(含行号) + 权威锚点
   ▼
G2 派生关系实测                     ← 新节点,喂平台CSV+日志
   │      输出: suffix_len / 头尾码 strip / 量化结论(可执行)
   ▼
C  生成四件套(拆小,G6)             ← 分次生成,降低截断
   ▼
D  五维硬自检(G3)                   ← 抽全率+重复率+1:1冲突+值合法性+平台列名
   │      值合法性: 含COM/含冒号/长度异常 → 判失败
   ▼
G4 审查者                           ← 新节点,挑配置逻辑漏洞
   │
   ▼ 不达标
G5 回炉(带完整证据, 上限5轮)        ← 自检报告+样例+当前配置一起喂回
   │
   ▼ 达标
写入 devices/<code>/ 四件套 + 返回质量报告
   │
G7 样例不足 → 标注推测正则, 提示真实日志验证
```

### G1 逐字段穷举(治多锚点/错绑源头)

把笼统的形态分析,拆成"每个字段一次调用",强制输出该字段的:
- 所有出现形态(含样例行号);
- 权威锚点(唯一、稳定、不重复)。

### G2 派生关系实测(治 MAC 硬约束错)

让 LLM 把平台 MAC 与追溯码摆一起,**数出**"MAC = 追溯码第几位到第几位";在日志里找 SN 真值的头/尾码,**推导剥离规则**;输出量化可执行结论(`suffix_len: 12`、`strip_suffix: "46"`)。

### G3 值合法性门槛(治 COM 口字段名)

抽出的字段值若 `含 COM / 含冒号 / 长度明显异常` → 直接判失败回炉。

### G4 审查者(一次调用换准确率)

生成完四件套后,再调一次 LLM 扮演审查者,输出逻辑漏洞清单,作为回炉输入。

### G5 回炉(带证据 + 上限放宽)

回炉时把**自检报告 + 原始样例 + 当前配置**一起喂回;上限放宽至 5 轮;仍不达标明确标「需人工补充规则」。

### G6 大任务拆小

四件套拆分生成/校验,单次输出更短,降低被推理模型 thinking 榨干的概率。

### G7 样例不足保守策略

标注推测正则,配合"生成后须真实日志验证再上生产"。

## 三、报告与界面(Part 3)

- 报告与前端展示「LLM 复核生效 / 空转告警」。
- 生成配置后展示自检质量报告(五维指标)。

## 四、影响面与兼容

| 模块 | 改动 | 兼容 |
|------|------|------|
| extractor | 派生可配/绑定/锚点唯一 | 老设备无派生规则→跳过,行为不变 |
| llm_review | 空转探针 | 仅新增 meta 字段 |
| device_generator | 多节点深挖管线 | 生成结果结构新增字段 |
| reporter | 复核生效标记 | 新增展示 |
| quality | 复用派生判据 | 无 |
| 四件套 schema | 扩展新键 | 向后兼容 |

## 五、风险

| 风险 | 缓解 |
|------|------|
| 权威形态某设备不存在 | 回退取首个锚点,不丢数据 |
| 派生长度个别设备不成立 | 长度可配置,生成期实测 |
| 生成期调用多导致慢 | 生成是一次性固定资产,慢可接受(用户明确"不限次数") |
| 推理模型仍榨干 | G6 拆小 + stop_reason 检测 + 重试 |
